# 二维码导出包分享设计

## 背景

二维码生成页会将最近生成的二维码图片压缩为 `二维码合计.zip`，当前仅支持通过局域网文件服务让电脑端下载。本次增加移动端系统分享入口，使用项目已有的 `share_plus` 依赖，将同一份 ZIP 分享到设备上可用的其他 App。

## 范围与交互

- 在现有“导出二维码”页增加“分享”按钮，与电脑端导出按钮并列。
- 分享内容为整个 `二维码合计.zip`，不拆分单张二维码图片。
- 点击分享后由 `share_plus` 打开系统分享面板。
- 分享成功后显示已分享状态；分享失败显示失败原因。
- 不改变现有文件服务启动、电脑端导出和返回二维码列表流程。

## 实现方案

`ExportPage` 复用已有的 `archive` 字节和 `filename`，通过 `XFile.fromData` 构造 MIME 类型为 `application/zip` 的分享文件，并调用 `Share.shareXFiles`。不写入临时目录，避免额外的文件生命周期管理。

为保持页面测试可验证，`ExportPage` 提供可选的分享回调；未传入时使用 `share_plus` 的生产实现。分享按钮处理忙碌状态，防止重复打开分享面板。调用分享 API 时传入按钮上下文对应的 `sharePositionOrigin`，兼容 iPad 的分享面板定位要求。

## 错误处理

- 分享过程中的异常由页面捕获，并显示 `分享失败: ...`。
- 分享失败不改变控制器的文件服务状态，也不清除待导出文件。
- 页面销毁后不再更新状态。

## 验证

- 增加 Widget 测试：分享按钮显示且使用传入的 ZIP 字节与文件名。
- 增加 Widget 测试：分享回调异常时显示失败状态。
- 运行二维码导出页相关测试和完整 `flutter test`，并运行 `flutter analyze`。

## 非目标

- 不新增独立分享服务或通用抽象。
- 不分享 ZIP 内的单张图片。
- 不改变现有电脑端下载协议。
