# 在线设备只读查看设计

## 目标

在移动端首页直接提供“在线扫码”和“在线查看全部”入口。用户只能扫码设备编号查看线上最新信息，或进入全部在线设备列表浏览详情；不提供新增、编辑、删除或保存能力，在线列表保留二维码生成和导出能力。

## 范围

- 首页新增“在线扫码”和“在线查看全部”两个入口。
- 扫码后调用线上 `query` 接口；请求期间显示“正在获取数据...”加载状态，以接口响应的数据展示只读详情。
- 点击“查看全部”后才加载线上列表；点击列表行展示只读详情，并保留二维码生成和导出能力。
- 在线设备流程隐藏所有修改类操作，在线列表保留二维码生成和导出操作。
- 在线列表隐藏 URL/Token 接口设置入口，但保留刷新和分页。
- 本地 Excel 导入和编辑流程不变。

## 页面与数据流

1. `HomePage` 直接显示“在线扫码”和“在线查看全部”两个入口，不新增在线设备中转页。
2. 用户选择“在线扫码”后，首页流程从 `OnlineConfigStore` 读取当前接口配置并打开扫码页，但不加载设备列表。
3. 扫码完成后，首页流程调用 `DeviceApi.queryDevice(deviceNo)`：
   - 成功时，将接口返回的完整行数据传给 `DeviceDetailPage`。
   - 请求期间首页显示加载状态并禁用入口；设备不存在、网络错误或接口异常时，仅显示错误提示并停留在首页；不得回退使用已加载的旧行数据。
4. 用户选择“在线查看全部”后，进入 `OnlinePage(readOnly: true)`。该页按既有分页逻辑调用 `DeviceApi.listDevices`，并保留刷新与分页加载。
5. 只读列表点击行时，将该行转换为字段映射并打开 `DeviceDetailPage`；详情页只显示字段和值，不含输入框、保存或删除操作。

## 组件职责

- `HomePage`：提供在线扫码、在线查看全部和既有本地配置入口；负责在线扫码后的实时查询和查询错误提示。
- `OnlinePage`：继续负责线上列表的加载、刷新和分页；新增 `readOnly` 模式后不向表格传递修改或删除回调。
- `SpreadsheetPage`：新增显式只读模式和只读行点击回调。只读模式隐藏新增、扫码、保存及长按删除动作；传入二维码导出构造器时保留二维码生成入口，默认行为保持现状，以避免影响本地表格。
- `DeviceDetailPage`：新建只读设备详情页面，接收字段映射并以可滚动的标签和值展示。

## 交互约束

- 首页提供“在线扫码”和“在线查看全部”两项在线主操作；请求期间显示加载状态。
- 在线列表不得显示新增、扫码、保存或删除入口；允许通过现有二维码生成页导出二维码。
- 在线列表不得显示 URL/Token 接口设置入口，但保留刷新和分页操作。
- 在线列表的设备编号匹配不再决定扫码结果；扫码始终以本次 `query` 响应为准。
- 列表的首次加载和手动刷新仍从线上读取，不在应用内持久化设备行数据。

## 错误处理

- 未配置接口：提示用户先配置接口。
- 扫码取消：不改变首页状态。
- 查询失败或设备不存在：展示接口返回的错误消息，不打开详情页。
- 列表加载失败：保持现有错误页和刷新机制。

## 验收与测试

- 进入首页不调用列表接口，且显示两个在线入口操作。
- 扫码查询期间显示“正在获取数据...”；查询完成后详情中展示该响应里的最新“计量日期”或“计量有效期至”。
- 扫码查询失败时不显示旧详情，也不进入编辑页面。
- 点击“查看全部”后才调用列表接口；列表行点击打开只读详情，不显示输入框或保存按钮。
- 在线列表显示二维码生成入口并可继续导出二维码，不显示新增、扫码、保存和删除入口。
- 在线列表不显示 URL/Token 设置入口，刷新入口仍可用。
- 本地 `SpreadsheetPage` 默认模式的新增、编辑、删除、扫码与二维码功能继续通过既有测试。
