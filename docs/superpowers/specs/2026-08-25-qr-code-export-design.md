# 二维码生成与导出设计

## 目标

在 Excel 表格编辑页面增加二维码入口。用户进入二维码页面后，可以根据每条设备记录的“设备编号”和“设备名称”生成 PNG 图片，并把全部图片收集到文件夹 `A`，压缩为 `A.zip` 后沿用现有电脑端文件服务导出到电脑默认下载目录。

## 页面与数据流

`SpreadsheetPage` 在工具栏提供二维码按钮。按钮打开 `QrCreatePage`，传入当前页面正在编辑的表头和行数据，因此二维码使用用户最新编辑结果，不依赖先保存 Excel 文件。

`QrCreatePage` 根据表头精确查找“设备编号”和“设备名称”列。页面展示有效设备记录，提供“生成”和“导出”按钮，并在操作期间展示明确状态：

- 生成过程中显示“生成中”；全部 PNG 创建成功后显示“生成已完成”。
- 导出过程中依次显示“压缩中”“导出中”；电脑端服务成功接收导出任务后显示“导出已完成”。
- 任一步骤失败时保留页面，显示失败原因，并允许用户重新操作。

## PNG 内容与命名

每条有效设备记录生成一张 PNG：

- 左侧为二维码，二维码编码内容为设备编号字符串。
- 右侧上方显示设备编号，右侧下方显示设备名称。
- 图片生成使用项目已有的 `qr_flutter` 依赖和 Flutter 绘制 API，不新增二维码库。
- 文件名为 `设备编号+设备名称.png`。文件名中的系统不允许字符替换为 `_`；同名文件追加序号，避免覆盖。

“有效设备记录”要求两个字段都存在且去除首尾空白后非空。缺少必要表头时页面提示“表格缺少设备编号或设备名称列”；没有有效记录时提示“没有可生成的设备数据”。

## 文件与导出

生成阶段将 PNG 写入应用文档目录下的 `A` 文件夹。每次重新生成前清理 `A` 文件夹中的旧 PNG，避免旧设备图片混入本次导出。

导出阶段将 `A` 文件夹中的 PNG 打包成 `A.zip`，通过现有 `FileServer` 的导出队列传输。电脑端继续使用现有轮询和默认下载行为，因此与 Excel 导出目录一致；浏览器支持目录选择时仍可使用用户选择的目录。导出响应使用 ZIP 的 MIME 类型和 `A.zip` 文件名。

## 错误处理

- 未生成图片时点击导出，提示先生成二维码。
- 生成或导出期间禁用对应操作按钮，防止并发写入和重复导出。
- 文件创建、压缩或文件服务未启动时捕获异常，状态显示“失败: 原因”，不关闭页面。
- 页面销毁后不再更新状态，避免异步任务触发已释放页面的状态异常。

## 测试策略

- 为设备记录提取和文件名清理添加单元测试，覆盖缺少列、空值、非法字符和重复名称。
- 为 PNG 生成和 ZIP 内容添加单元测试，确认生成文件存在、扩展名正确、压缩包包含所有 PNG。
- 为 `SpreadsheetPage` 添加二维码按钮和跳转行为测试。
- 为 `QrCreatePage` 添加生成/导出按钮状态和成功状态文案测试。
- 运行 `flutter test`、`flutter analyze`；条件允许时运行目标桌面构建验证插件和文件服务兼容性。
