# 在线设备自动加载全部设计

## 背景

在线设备页进入时自动加载第一页，后续分页依赖用户上拉触底或手动刷新。数据量较大时，用户需要反复操作才能查看完整列表。本次增加一个“自动加载全部”按钮，点击后连续按接口返回的 `nextStart` 加载所有分页。

## 范围与交互

- 默认进入页面的行为保持不变，先加载第一页。
- 在在线设备页顶部工具栏增加“自动加载全部”按钮。
- 只有当前列表存在下一页且没有其他加载任务时按钮可用。
- 点击按钮后自动连续请求下一页，直到 `hasMore=false`，期间不需要刷新或上拉。
- 在现有计数后追加加载状态，例如 `已加载100/260条数据，正在加载第3页`。
- 首次加载期间显示 `正在加载第一页`；全部加载完成后显示 `已全部加载完成260条数据`。
- 自动加载期间禁用刷新、配置和其他分页加载入口，避免并发请求。

## 实现方案

`OnlinePage` 继续复用 `_loadPage` 的单页请求和 `nextStart` 处理，新增自动加载循环、已加载页数和自动加载状态。每次请求前更新当前页文案，请求完成后按接口返回的 `hasMore` 决定是否继续。

`SpreadsheetPage` 增加可选的分页状态文本参数，仅负责将它拼接到现有 AppBar 计数文案中。在线页在首次加载页和表格页都传入该状态，使首次加载和已有数据上的自动加载都能显示进度。现有触底加载和下拉刷新回调接口不变。

## 错误处理与并发

- 自动加载过程中任一页失败时停止后续请求，保留已经加载的数据，并复用现有错误提示。
- 自动加载按钮、刷新按钮、配置按钮和触底加载在自动加载期间均不可重复触发。
- 每次自动请求必须使用接口返回的 `nextStart`；若分页位置未推进则停止并提示错误，避免异常接口导致无限循环。
- 页面销毁后不再更新状态。

## 验证

- Widget 测试确认默认进入只请求第一页。
- Widget 测试点击“自动加载全部”后按 `nextStart` 连续请求，并展示第二页等状态。
- Widget 测试确认完成后显示全部加载完成，且不会多请求。
- Widget 测试确认分页失败时停止并保留错误状态。
- 运行在线页相关测试、完整 `flutter test` 和 `flutter analyze`。

## 非目标

- 不改变远端接口参数、`hasMore` 或 `nextStart` 协议。
- 不改变现有手动刷新和触底加载的默认行为。
- 不增加新的依赖或独立分页服务。
